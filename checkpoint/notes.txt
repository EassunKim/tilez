## Game rules (as decided)
- Single player. (Two-player — same level in sequence, fewest moves wins — is a
  STRETCH GOAL for later this term, not part of the current spec. This is a change
  from the submitted Checkpoint 1 spec.)
- Grid of tiles surrounded by void. Player moves/rotates; ally mirrors every input.
- If the player is blocked, the ally still moves if it can (the desync mechanic).
- Win: ally reaches the goal tile (`T_GOAL`, 'G'). Player on the goal does nothing.
- Fire tile (either character): reset to spawns; move counter is NOT reset.
- Slip tile: the character on it moves one extra cell if free; otherwise stays on it.
  Chained slips: not yet decided.
- Player and ally cannot share a tile; they block each other. Player resolves first,
  then the ally using the player's new position.
- Move counter: one counter. Forward moves only, and only if at least one character
  moved. Rotations don't count.
- Spawn positions and facings are per level (spec text said "center, facing each
  other" — this is a deliberate change).
- Controls: W forward, A left, D right, S turn around.

## Model design decisions
- Positions are grid cells, grid indexed `[y][x]` (row first, row 0 = top), same
  order as level row strings. Renderer converts: cell * 32 px.
- Tiles are 32x32 px; grid up to 10x10 (320x320 px). `GRID_WIDTH`/`GRID_HEIGHT` live
  in tile.h.
- Directions: `#define NORTH 0, EAST 1, SOUTH 2, WEST 3` (clockwise) in player.h.
  Rotate right +1, left +3, around +2, wrapped with `% 4` (mod is fine in the model;
  the no-mul/div rule is raster only).
- Player and ally share the `Player` type (x, y, facing all UINT8).
- `player_forward_cell` outputs INT16 so off-grid north/west gives -1, not 255.
- Normal/Fire/Slip/Goal/Void are one Tile object with a `type` field. Values are
  contiguous so the renderer can index a bitmap array by type:
  `T_VOID 0, T_NORMAL 1, T_GOAL 2, T_SLIP 3, T_FIRE 4`. (`T_SAFE` was removed.)
- Walls are bit flags on tiles: bit = `1 << direction`
  (`WALL_NORTH 0x01, EAST 0x02, SOUTH 0x04, WEST 0x08`). A wall only needs to be set
  on one of the two tiles; the move check tests both sides. `tile_add_wall` and
  `tile_check_walls` take a DIRECTION, never a WALL_* mask.
- Tile types are `#define`s, not an enum (enum would be 16 bits here).
- Levels are written as row strings (`.` normal, `F` fire, `S` slip, `G` goal,
  space = void; short rows are void past the end) plus a separate wall list
  (`wallInfo {x, y, side}`, side = direction). `Level` holds `const char *rows[]`,
  `const wallInfo *walls`, `wall_count`, player/ally spawns. `levels.c` owns the
  format; model only calls `level_get` and `level_build_grid`.
- Walls are applied after rows are built (tile_init zeroes walls).

## Model plan
- Model struct: `Tile grid[GRID_HEIGHT][GRID_WIDTH]`, player, ally, player/ally spawns,
  one move counter, level_complete, current level index. (No current_player / per-player
  counters — multiplayer is a stretch goal.)
- model.c functions:
  - static: in-bounds check; try-step-forward (returns whether it moved).
  - `model_load_level`: level_get (stop on NULL), build grid, copy spawns, zero
    counter, clear level_complete, store level index, reset positions.
  - `model_reset_level`: copy spawns into player/ally; leave counter.
  - `model_tile_at(x, y)`: T_VOID off-grid, else the cell's type.
  - `model_can_enter(model, mover, other)`: blocked by void, wall on mover's facing
    side, wall on next tile's opposite side, or the other character on that cell.
  - `model_move_forward`: player then ally; increment counter if either moved.
  - rotate left/right/around: both characters, no count.
  - `model_slip(model, who, other)`: one more step if possible.
- `asynch.c`, `synch.c` (likely near empty), `cond.c` (slip, fire, goal checks after a
  move; cond sets level_complete) — after model.c.
- Model test driver — after that. Then renderer. If short on time, keep the renderer
  minimal rather than cutting model tests.
